# Amar Iptv publishing readiness

Checked: 5 November 2026, Asia/Riyadh. Scope: Google Play for Android phone/tablet and Android TV/Google TV. Other stores and TV operating systems need separate plans.

This is a readiness audit, not permission to submit a release, register/pay for an account, or change the approved product scope. Verified means the stated evidence was inspected; it does not imply physical-device or production readiness.

## Current baseline

Verified: v0.9.0/code11, merged main c83b334 through PR18. PR72 and main73 each passed all five jobs, actual86 phone and86 TV cases without failures/errors/skips and all source/progress cold-process probes. Evidence: ignored .tools/ci/cw-pr18/run72/verification.json and main73/verification.json. Independent feature and final-commit reviews passed.

Implemented: file/M3U URL/Xtream-compatible entry, multiple protected local sources, cached catalogues/manual refresh, paged browsing/categories/search/favourites, Live/Movies/Series, provider-supplied basic artwork/year/rating, EN/AR and RTL, dark/light Cinema UI, TV remote navigation, real Media3 playback with native controls and30s seeks, local movie/episode progress and Continue Watching. Optional filtered PostHog monitoring is integrated. This is not a claim that every provider or codec works.

Baseline source checks at c83b334: application ID com.fireamun.iptv.prototype, minSdk28, target/compile36; only INTERNET declared in the app manifest; backup disabled; cleartext HTTP enabled. The then-current catalogue cap was100,000, parser default64MiB/16,384 code units per line/512 per field/120s. App Gradle has no release signing configuration or Billing dependency. The inspected debug APK contains AndroidX graphics path native libraries for ARM32/ARM64/x86/x86_64; native compatibility therefore needs verification despite Kotlin application code. No app Privacy/About or analytics preference entry point was found in the inspected production sources.

Capacity follow-up,6 November2026: candidate0.10.0 validates a300k count guard with measured storage-memory fixes; see the [capacity report](catalogue-capacity.md) and tracker for current delivery. Physical hardware and all other publication gates below remain open.

## Suggested order

Owner legal/onboarding proposal,5 November: add Settings > Legal & About with Terms of Use, Privacy Policy, third-party notices and support/copyright contact. Terms of Service and Terms of Use can be one document. Proposed first-launch screen before source entry: short player-only/no-supplied-content summary, requirement to use authorized sources, linked full documents, explicit unchecked Terms acceptance with Agree and continue/Decline. Explain any purchase covers player functionality, not a content subscription. Keep analytics choices separate from Terms acceptance and assess any required consent before collection. Store accepted Terms version/time locally; request renewed agreement for relevant material changes, not each playback. English/Arabic, offline-readable text and remote-accessible TV controls should match published versions. The owner approved this proposal on 17 November 2026 and it was implemented on 21 November 2026 as drafts (Terms version 1, Saudi law, developer name Amar Elshaer). The text is a careful draft, not reviewed legal advice; jurisdiction-appropriate review is still advised before any paid launch.

Do not promise that a disclaimer eliminates owner liability. Google prohibits encouraging infringement; statutory duties and non-excludable rights remain. Saudi Civil Transactions Law Article173 restricts contractual exemptions for fraud/gross negligence and bars exemption from liability for a harmful act. Final operator identity/jurisdiction, liability, purchase/refund and privacy clauses need jurisdiction-appropriate review before paid publication. Sources checked5 November: [Play intellectual property policy](https://support.google.com/googleplay/android-developer/answer/9888072), [privacy/disclosure policy](https://support.google.com/googleplay/android-developer/answer/10144311), [official Saudi law translation](https://misa.gov.sa/app/uploads/2025/07/Civil-Transactions-Law.pdf). No assertion is made that a generic clause settles all Saudi/Egyptian liability questions.

1. Check the Play account/production-access situation and choose first-release scope and commercial offer early; these determine the longest external gates.
2. Finish the measured300k delivery and begin S25/selected-TV compatibility evidence in parallel with release preparation when hardware is available.
3. Complete selected missing product features, credential transport resolution, privacy/SDK controls and billing if charging.
4. Finalize identity/signing and build the release AAB; run Play-distributed device, pre-launch and purchase tests.
5. Complete store assets/declarations/reviewer access and any applicable closed-test period, fix feedback, then obtain owner authorization for public submission/launch.

Full P3/P4/P5 scope and Google Play readiness are separate milestones. There is no defensible completion percentage or launch date until the account state, launch scope, offer and device results are known.
